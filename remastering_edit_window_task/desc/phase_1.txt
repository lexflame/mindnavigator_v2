3. РЕАЛИЗОВАННЫЕ ИЗМЕНЕНИЯ
===============================================================================

3.1. Новое поле важности задачи

Добавлено независимое поле importance со значениями от 1 до 5.
В интерфейсе оно отображается звездами.

Изменены:
    mindnavigator/storage/database_schema_mixin.py
    mindnavigator/storage/database_tasks_mixin.py
    mindnavigator/storage/task_data.py
    mindnavigator/workspaces/tasks/task_row.py
    mindnavigator/workspaces/tasks/tasks_model.py
    mindnavigator/workspaces/tasks/tasks_item_delegate.py
    mindnavigator/workspaces/tasks/task_edit_dialog.py
    mindnavigator/workspaces/tasks/task_details_dialog.py
    mindnavigator/workspaces/tasks/task_property_propagation.py

Схема:
    migration v13: task_importance_schema
    tasks.importance INTEGER NOT NULL DEFAULT 3
    значение нормализуется в диапазон 1..5 при чтении и записи.

3.2. Комментарии к изображениям внутри задачи

Для вложений задачи добавлено поле comment. Комментарий относится к конкретной
связи task_attachments, а не к глобальному файлу.

Изменены:
    mindnavigator/storage/database_schema_mixin.py
    mindnavigator/storage/database_tasks_mixin.py
    mindnavigator/storage/task_attachment_data.py
    mindnavigator/workspaces/tasks/task_image_preview_dialog.py
    mindnavigator/workspaces/tasks/task_edit_dialog.py
    mindnavigator/workspaces/tasks/task_details_dialog.py

Схема:
    migration v14: task_attachment_comment_schema
    task_attachments.comment TEXT NOT NULL DEFAULT ''

API хранения:
    update_task_attachment_comment(attachment_id, comment)

Поведение:
    - В preview-режиме комментарий отображается только для чтения.
    - В edit-режиме комментарий можно менять и сохранять.

3.3. Расширение и стилизация окна задачи

TaskDetailsDialog стал широким контейнером:
    default size: 1360 x 820
    minimum size: 1180 x 720

Основной файл:
    mindnavigator/workspaces/tasks/task_details_dialog.py

Реализованы:
    - двухколоночная компоновка содержимого;
    - отдельные блоки описания, связей, изображений, деталей и навигатора
      концептборда;
    - сворачиваемые блоки связей и изображений;
    - открытие прикрепленных сущностей;
    - открытие связанных задач карточкой TaskDetailsDialog;
    - кнопки навигатора концептборда по прикрепленным сущностям;
    - статусные badges;
    - увеличенное frameless-окно без минимизации.

3.4. Inline-редактирование отдельных полей

В TaskDetailsDialog добавлен InlineEditableField.
Двойной клик по отдельным значениям позволяет менять поле без открытия
дополнительного диалога.

Поддерживаются:
    - название;
    - проект;
    - дата;
    - время;
    - приоритет;
    - важность;
    - повтор;
    - статус;
    - цвет маркера;
    - тема маркера;
    - описание.

3.5. Единый контейнер preview/edit для существующей задачи

Ключевой рефакторинг phase 1:
    Редактирование существующей задачи больше не открывает второй TaskEditDialog.
    Кнопка "Редактировать" переключает текущий TaskDetailsDialog в edit-режим.

Методы:
    TaskDetailsDialog._open_edit_dialog()
    TaskDetailsDialog._set_form_editing(enabled)
    TaskDetailsDialog._save_form_updates()
    TaskDetailsDialog._cancel_or_close()

Поведение:
    - В preview-режиме верхние действия: "Закрыть", "Редактировать".
    - В edit-режиме верхние действия: "Отменить", "Сохранить".
    - Esc отменяет edit-режим без записи.
    - Сохранение использует TasksModel.update_task_by_row(), если модель доступна.
    - При отсутствии модели используется прямое обновление через database facade.
    - Ошибка валидации не закрывает edit-режим.

Старый TaskEditDialog намеренно сохранен:
    - он еще используется для создания задачи;
    - он остается совместимым fallback-контейнером;
    - удалять его до завершения миграции всех сценариев нельзя.

3.6. Управление связями и изображениями из единого контейнера

В edit-режиме TaskDetailsDialog:
    - блоки связей и изображений раскрываются автоматически;
    - доступно добавление связи;
    - доступно прикрепление изображения;
    - у существующих связей и изображений появляются кнопки удаления.

Методы:
    TaskDetailsDialog._open_attachment_dialog(kind=None)
    TaskDetailsDialog._attachment_candidates(kind)
    TaskDetailsDialog._remove_attachment(attachment)

3.7. Последняя правка верхней зоны по уточнению пользователя

Требование:
    1. Заголовок окна должен показывать название задачи.
    2. Под заголовком должна быть одна строка ровно из пяти блоков:
       - Название задачи
       - Проект
       - Срок выполнения
       - Приоритет
       - Важность задачи

Реализовано в commit:
    3177fe2 feat: align task header parameter row

Текущая структура:
    - Заголовок окна: отдельный QLabel TaskDetailsTitle.
    - Верхняя строка: пять _InfoCard в фиксированном порядке.
    - Срок выполнения объединяет дату и время.
    - Верхний ряд принудительно всегда содержит пять колонок:
      _PARAM_BREAKPOINTS = ((0, 5),)
    - Повтор, статус и GANTT перенесены в блок "Детали".

6. ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ И НЕЗАВЕРШЕННЫЕ ЧАСТИ
===============================================================================

6.1. Нужна ручная визуальная проверка после последнего commit

Автотесты проверяют структуру и поведение, но не пиксельное соответствие.
После 3177fe2 приложение еще не сравнивалось новым скриншотом с PNG-прототипами.

6.2. Верхняя строка принудительно остается из пяти колонок

Это прямое требование пользователя. На узком окне элементы могут стать плотными.
Минимальная ширина диалога 1180 px должна ограничить проблему, но нужна ручная
проверка реального отображения длинного названия задачи и длинного проекта.

6.3. Диалог добавления связей в TaskDetailsDialog пока базовый

В новом едином контейнере используется локальный QComboBox-селектор.
Старый TaskEditDialog содержит более развитый сценарий:
    - FilterableComboBox;
    - выбор файла через AttachFileSelectNav;
    - дополнительные подписи сущностей.

Следующий рефакторинг должен извлечь общий reusable attachment selector и
использовать его в обоих контейнерах, чтобы не поддерживать две реализации.

6.4. Старый TaskEditDialog еще не декомпозирован

Для существующих задач основной путь уже проходит через TaskDetailsDialog.
TaskEditDialog по-прежнему нужен для create flow и содержит собственные блоки
связей, изображений и формы. Следующий крупный этап: извлечь переиспользуемые
QWidget-компоненты и постепенно убрать дублирование.

6.5. Markdown toolbar не является полноценным rich text editor

В TaskEditDialog добавлен toolbar для markdown-действий. Он сохраняет markdown
формат и не превращает описание в HTML/WYSIWYG. Это осознанное ограничение
текущей фазы, чтобы не ломать существующее хранение description.

6.6. GANTT пока представлен прежним редактором длительности

Прототип показывает более развитый блок с планом, затраченным временем,
остатком и progress bar. В текущей реализации сохранен существующий
GanttEstimateEdit. Полный визуальный GANTT-блок еще не реализован.

6.7. Навигатор концептборда функционально базовый

Сейчас он строит до четырех кнопок по прикрепленным сущностям.
В прототипе показан оформленный маршрут с узлами и стрелками.
Нужна дальнейшая визуальная проработка и уточнение поведения добавления контента.

6.8. Preview/edit parity еще не завершен

В прототипах preview и edit имеют более точные различия:
    - toolbar описания;
    - плотность карточек;
    - chip-оформление связей;
    - карусель изображений;
    - нижняя metadata/status панель;
    - progress bar GANTT;
    - визуальные иконки.

Текущий этап создает правильную архитектурную основу, но не является финальным
пиксельным remaster.

10. ИТОГ PHASE 1
===============================================================================

Phase 1 завершила архитектурный переход от отдельного окна просмотра и отдельного
окна редактирования существующей задачи к единому TaskDetailsDialog с режимами
preview/edit. Добавлены важность задачи, комментарии изображений, базовое
управление связями и структура верхней строки по последнему уточнению пользователя.

Следующая фаза должна начинаться с нового визуального скриншота и продолжаться
через устранение расхождений с прототипом и извлечение общих компонентов из
TaskDetailsDialog и TaskEditDialog.
