# P3-03: UX thresholds and 5k verification

Local reference thresholds for synchronous desktop operations:

| Operation | p95 threshold |
| --- | ---: |
| `fetch_tasks` | 250 ms |
| `global_search` | 100 ms |
| `tasks_model_reload` | 500 ms |
| task/project dialog construction | 500 ms |

These are diagnostic thresholds, not CI pass/fail limits. A worker or additional debounce is justified only when a repeatable local p95 exceeds the corresponding threshold.

Fixture and command:

```powershell
python -m scripts.run_perf_benchmarks .test_runtime/p3_02_perf_5k.sqlite3 --iterations 10 --warmup 2 --query "Performance task 000001"
```

Results after replacing repeated full task reads with targeted hierarchy queries and fixing deferred widget deletion in the runner:

| Operation | p50 ms | p95 ms | Mean ms |
| --- | ---: | ---: | ---: |
| `fetch_tasks` | 151.398 | 160.361 | 152.349 |
| `global_search` | 2.482 | 3.567 | 2.708 |
| `tasks_model_reload` | 283.970 | 335.732 | 297.212 |
| `task_edit_dialog_open` | 190.689 | 225.419 | 196.013 |
| `project_edit_dialog_open` | 263.814 | 307.867 | 273.498 |

All measured p95 values are below their UX thresholds. No Qt UI construction was moved to a worker thread.
