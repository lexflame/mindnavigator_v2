# ТЗ для CODEX CLI: переработка окна просмотра и редактирования проекта в MindNavigator

## 1. Назначение задачи

Необходимо переработать текущее окно редактирования проекта в desktop-приложении MindNavigator на Python.

Текущее окно редактирования проекта выглядит как длинная вертикальная форма со списком полей. Необходимо заменить его на современную карточку просмотра и редактирования проекта по методике, выработанной для окна задачи:

- единая форма для просмотра и редактирования;
- верхний блок с названием проекта и ключевыми свойствами;
- двухколоночная компоновка;
- карточки-секции;
- локальное редактирование отдельных полей по двойному клику;
- переход к связанным сущностям по одиночному клику;
- общий режим редактирования всей формы по кнопке `Редактировать`;
- Bootstrap 4-подобные паттерны, адаптированные под PySide6;
- тёмная тема MindNavigator;
- QSS-стилизация без изменения общей цветовой схемы приложения.

Окно должно перестать быть технической формой настроек и стать полноценной карточкой управления проектом.

## 2. Технологический контекст

Реализация выполняется для desktop-приложения MindNavigator.

Основной стек:

- Python;
- PySide6;
- Qt Widgets;
- QSS;
- SQLite;
- существующая архитектура MindNavigator;
- существующие модели проектов, задач, маркеров, связей, репозиториев и wiki.

Необходимо найти текущую реализацию окна редактирования проекта и заменить или расширить её новым интерфейсом.

Если в проекте уже есть общие виджеты, разработанные для окна задачи, необходимо переиспользовать их.

## 3. Визуальный ориентир

Визуально окно проекта должно соответствовать стилю нового окна редактирования задачи:

- тёмный сине-графитовый фон;
- компактные карточки;
- мягкие границы;
- фиолетово-синие акценты;
- input-group-поля;
- dropdown-поля;
- chip/badge-представление связей;
- аккуратная нижняя панель действий;
- читаемые заголовки блоков;
- визуальная иерархия без перегруза.

Не менять текущую цветовую схему MindNavigator.

## 4. Главная цель интерфейса

Пользователь должен быстро видеть:

- какой проект открыт;
- к какой области относится проект;
- когда проект обновлялся;
- какой у него приоритет;
- есть ли родительский проект;
- какие правила проекта наследуются задачами;
- какие сущности связаны с проектом;
- какие репозитории и wiki относятся к проекту;
- какие типы задач используются в проекте;
- архивирован ли проект;
- какая статистика есть по задачам проекта.

Окно должно работать как рабочий центр проекта.

## 5. Общая компоновка окна

Форма состоит из трёх основных зон:

1. Верхний блок.
2. Левая колонка 50%.
3. Правая колонка 50%.

Схема:

```text
┌────────────────────────────────────────────────────────────────────┐
│ Верхний блок: название проекта, область, дата, приоритет, parent    │
├──────────────────────────────────┬─────────────────────────────────┤
│ Левая колонка 50%                │ Правая колонка 50%              │
│ Основное                         │ Свойства                        │
│ Связи                            │ Иерархия и правила              │
│ Типы задач                       │ Поведение задач по умолчанию    │
│ Репозитории / Wiki               │ Статистика / активность         │
└──────────────────────────────────┴─────────────────────────────────┘
```

## 6. Размеры окна

Рекомендуемые размеры:

- минимальная ширина: 1100 px;
- рекомендуемая ширина: 1200-1280 px;
- минимальная высота: 700 px;
- рекомендуемая высота: 760-820 px.

Окно должно корректно масштабироваться.

При малой высоте:

- верхний блок остаётся сверху;
- нижняя панель действий остаётся доступной;
- содержимое колонок прокручивается;
- карточки не должны налезать друг на друга.

## 7. Тип окна

Допустимые варианты:

- `QDialog`;
- кастомный `QWidget` поверх основного интерфейса;
- modal-like overlay;
- встроенная центральная панель.

Предпочтительный вариант: широкое диалоговое окно или overlay-панель в стиле окна задачи.

Окно должно поддерживать:

- закрытие по кнопке;
- закрытие по `Esc`;
- сохранение по `Ctrl+S`;
- сохранение и закрытие по `Ctrl+Enter`;
- переход всей формы в режим редактирования по `Ctrl+E`;
- предупреждение при закрытии с несохранёнными изменениями.

## 8. Режимы формы

Форма должна быть единой для просмотра и редактирования проекта.

Не должно быть двух разных окон: отдельно просмотр и отдельно редактирование.

### 8.1. Режим просмотра

В режиме просмотра:

- поля отображаются как текст, badge, chip, карточки и compact-value;
- dropdown не выглядит как активный input;
- связанные сущности открываются по одиночному клику;
- кнопка `Редактировать` переводит всю форму в режим редактирования;
- опасные действия скрыты или находятся в дополнительном меню;
- форма должна выглядеть спокойно и читабельно.

### 8.2. Режим редактирования всей формы

По нажатию кнопки `Редактировать` вся форма переходит в режим редактирования.

В этом режиме:

- все редактируемые поля становятся активными;
- dropdown-поля можно раскрывать;
- текстовые поля становятся input/textarea;
- связи можно добавлять и удалять;
- типы задач можно добавлять и удалять;
- репозитории и wiki можно редактировать;
- доступны кнопки `Сохранить` и `Отменить`.

Кнопка `Сохранить` сохраняет все изменения одной транзакцией или единым вызовом сервисного слоя.

Кнопка `Отменить` откатывает все несохранённые изменения.

### 8.3. Локальное редактирование отдельного поля

Каждое редактируемое поле должно поддерживать локальное редактирование по двойному клику.

Правило:

- одиночный клик по сущности открывает сущность;
- двойной клик по редактируемому полю переводит только это поле в режим редактирования;
- остальные поля остаются в режиме просмотра;
- после сохранения поле возвращается в режим просмотра;
- после отмены поле возвращается к последнему сохранённому значению.

Поля для локального редактирования:

- название проекта;
- область;
- дата обновления;
- приоритет;
- parent project;
- task priority preset;
- force recurrence;
- linked map;
- linked note;
- linked object;
- маркер цвета;
- тема маркера;
- каталог репозитория;
- репозитории;
- wiki;
- связанные проекты;
- связанные задачи;
- типы задач;
- архивный статус.

Для реализации использовать общий компонент `InlineEditableField` или существующий аналог.

### 8.4. Разрешение конфликта одиночного и двойного клика

Для полей-ссылок нужно различать одиночный и двойной клик:

- одиночный клик открывает связанную сущность после небольшой задержки;
- двойной клик отменяет действие одиночного клика и открывает локальное редактирование;
- если поле не редактируется, двойной клик повторяет открытие сущности или ничего не делает.

Поведение должно быть единым для всех сущностей.

## 9. Верхний блок

Верхний блок занимает 100% ширины окна.

### 9.1. Состав верхнего блока

Верхний блок содержит:

- крупное название проекта;
- подпись режима: `Просмотр проекта` или `Редактирование проекта`;
- область;
- дата обновления;
- приоритет;
- parent project;
- кнопки `Закрыть` / `Редактировать` в режиме просмотра;
- кнопки `Отменить` / `Сохранить` в режиме редактирования.

### 9.2. Название проекта

Название проекта должно быть главным визуальным элементом окна.

В режиме просмотра:

```text
MindNavigator v2
Просмотр проекта
```

В режиме редактирования:

```text
MindNavigator v2
Редактирование проекта
```

В режиме локального редактирования название превращается в input.

Требования:

- пустое название запрещено;
- максимальная длина должна соответствовать текущей модели;
- при ошибке показывать inline-валидацию.

### 9.3. Ключевые поля верхнего ряда

Верхний ряд должен содержать компактные карточки/input-group:

```text
[ Область: SPACE ▼ ] [ Дата обновления: 06.01.2026 📅 ] [ Приоритет: High ▼ ] [ Parent project: None ▼ ]
```

Требования:

- не делать длинный вертикальный список;
- использовать крупные value-card элементы;
- каждое поле поддерживает двойной клик для локального редактирования;
- parent project по одиночному клику открывает родительский проект, если он задан.

## 10. Левая колонка

Левая колонка занимает 50% ширины.

Содержит:

- блок `Основное`;
- блок `Связи`;
- блок `Типы задач`;
- блок `Репозитории и Wiki`.

## 11. Блок `Основное`

### 11.1. Назначение

Блок содержит базовые данные проекта.

Поля:

- название;
- каталог репозитория;
- репозитории;
- wiki.

### 11.2. Визуальное представление

```text
Основное
[ Название              ][ MindNavigator v2                         ]
[ Каталог репозитория   ][ Путь к локальному репозиторию             ]
[ Репозитории           ][ MindNavigator Core | D:/_Branch/...       ]
[ Wiki                  ][ Project Wiki | https://docs.example.com   ]
```

### 11.3. Поведение

В режиме просмотра:

- путь к локальному репозиторию отображается как текст;
- wiki отображается как ссылка;
- одиночный клик по wiki открывает ссылку или внутренний wiki-раздел;
- одиночный клик по репозиторию может открывать каталог, если это поддерживается приложением.

В режиме редактирования:

- поля превращаются в input;
- для каталога репозитория должна быть кнопка выбора папки;
- для wiki должна быть проверка URL или внутреннего идентификатора wiki.

## 12. Блок `Связи`

### 12.1. Назначение

Блок отображает сущности, связанные с проектом.

Поля и сущности:

- связанные проекты;
- связанные задачи;
- linked map;
- linked note;
- linked object;
- файлы;
- репозитории;
- wiki.

### 12.2. Визуальное представление

Связи показывать как чипы, а не как многострочный input с ID.

Пример:

```text
Связи
[ Проект: MindCore × ] [ Проект: UI Kit × ]
[ Задача: Прототип окна задачи × ]
[ Карта: Roadmap SPACE × ]
[ Заметка: Project Wiki × ]
[ Объект: MindNavigator Core × ]
[ + Добавить связь ]
```

### 12.3. Поведение

В режиме просмотра:

- одиночный клик по чипу открывает связанную сущность;
- кнопки удаления скрыты;
- блок может быть сворачиваемым.

В режиме редактирования:

- можно добавить связь;
- можно удалить связь;
- можно открыть связанную сущность через отдельную иконку перехода;
- связи не должны редактироваться как сырой список ID, если можно показать сущности.

### 12.4. Окно добавления связи

По кнопке `+ Добавить связь` открывается модальное окно, примерно в половину размера основного окна.

Окно содержит:

- заголовок `Добавить связь`;
- выбор типа сущности;
- поле поиска;
- список результатов;
- кнопки добавления;
- блок выбранных связей;
- кнопки `Отменить` и `Добавить связь`.

Типы связей:

- проект;
- задача;
- карта;
- заметка;
- объект;
- файл;
- репозиторий;
- wiki.

## 13. Блок `Типы задач`

### 13.1. Назначение

Блок отображает типы задач, закреплённые за проектом.

В текущем окне поле выглядит как строка:

```text
DEV | #4C78D0 | dev | active
```

Нужно заменить это на chip/list-представление.

### 13.2. Визуальное представление

```text
Типы задач
[ DEV × ] [ #4C78D0 × ] [ dev × ] [ active × ] [ + ]
```

Допустимый улучшенный вариант:

```text
Типы задач
[ DEV | dev | active | #4C78D0 × ] [ + Добавить тип ]
```

### 13.3. Поведение

В режиме просмотра:

- типы задач отображаются как цветные или текстовые чипы;
- одиночный клик по типу открывает карточку типа, если такая сущность существует.

В режиме редактирования:

- можно добавить тип задачи;
- можно удалить тип задачи;
- можно отредактировать тип по двойному клику;
- цвет типа должен отображаться маленьким цветовым маркером.

## 14. Блок `Репозитории и Wiki`

### 14.1. Назначение

Блок хранит проектные технические ссылки.

Состав:

- каталог репозитория;
- список репозиториев;
- wiki;
- дополнительные ссылки, если они есть в модели.

Если эти поля уже находятся в блоке `Основное`, отдельный блок можно не создавать. Однако логически они должны быть сгруппированы и не перемешаны с правилами задач.

### 14.2. Поведение

- путь к локальному репозиторию можно выбрать через диалог папки;
- wiki можно открыть по одиночному клику;
- репозиторий можно открыть в файловом менеджере;
- при ошибке пути показывать предупреждение, но не блокировать открытие проекта.

## 15. Правая колонка

Правая колонка занимает 50% ширины.

Содержит:

- блок `Свойства`;
- блок `Иерархия и правила`;
- блок `Поведение задач по умолчанию`;
- блок `Статистика и активность`.

## 16. Блок `Свойства`

### 16.1. Назначение

Блок содержит свойства проекта, влияющие на задачи и отображение.

Поля:

- task priority preset;
- force recurrence;
- маркер цвета;
- тема маркера;
- архивировать проект.

### 16.2. Визуальное представление

```text
Свойства
[ Task priority preset ][ None ▼ ]
[ Force recurrence     ][ None ▼ ]
[ Маркер цвета         ][ None ▼ ]
[ Тема маркера         ][ None ▼ ]
[ Архивировать проект  ][ □ Архивировать проект ]
```

### 16.3. Поведение

Каждое поле поддерживает:

- просмотр;
- локальное редактирование по двойному клику;
- общий режим редактирования;
- валидацию значения;
- сохранение через сервисный слой проекта.

Архивный статус должен быть чекбоксом.

Изменение архивного статуса должно требовать подтверждения, если проект содержит активные задачи.

Пример подтверждения:

```text
Архивировать проект «MindNavigator v2»?
Активных задач: 24.
Проект будет скрыт из основных списков, но останется доступен через архив.
[ Отмена ][ Архивировать ]
```

## 17. Блок `Иерархия и правила`

### 17.1. Назначение

Блок отвечает за родительский проект и наследование правил.

Поля:

- parent project;
- наследование приоритета задач;
- наследование повторяемости;
- наследование маркеров;
- локальные переопределения.

Если в текущей модели есть только `Parent project`, `Task priority preset`, `Force recurrence`, необходимо визуально показать, что эти свойства относятся к правилам проекта.

### 17.2. Визуальное представление

```text
Иерархия и правила
[ Parent project ][ None ▼ ]

Поведение задач по умолчанию
[ Preset не задан ][ Настроить... ]

Подсказка:
Настройки поведения задач, повторяемости, напоминаний и другие правила наследуются из родительского проекта или глобальных параметров системы.
```

### 17.3. Поведение

- одиночный клик по parent project открывает родительский проект;
- двойной клик переводит поле в режим выбора parent project;
- нельзя выбрать проект родителем самого себя;
- нельзя создать циклическую иерархию проектов;
- при смене parent project нужно предупредить о возможном изменении наследуемых правил.

## 18. Блок `Поведение задач по умолчанию`

### 18.1. Назначение

Блок задаёт правила, которые применяются к новым задачам проекта.

Параметры-кандидаты:

- task priority preset;
- force recurrence;
- маркер цвета по умолчанию;
- тема маркера по умолчанию;
- статус новых задач;
- исполнитель по умолчанию, если поддерживается;
- планировать новые задачи по умолчанию, если поддерживается;
- срок по умолчанию, если поддерживается.

### 18.2. Поведение

Кнопка `Настроить...` открывает отдельное дочернее окно или раскрываемую панель.

В этом окне можно задать правила для новых задач проекта.

Необходимо использовать уже существующие поля модели, а недостающие поля добавлять только через безопасные миграции.

## 19. Блок `Статистика и активность`

### 19.1. Назначение

Блок показывает быстрый обзор состояния проекта.

Минимальный набор:

- всего задач;
- активных задач;
- выполненных задач;
- просроченных задач;
- дата последнего обновления;
- количество связанных сущностей.

Пример:

```text
Статистика
Задач: 24
Активных: 12
Готово: 8
Просрочено: 4
Связей: 6
```

### 19.2. Поведение

- блок доступен в режиме просмотра;
- в режиме редактирования может оставаться read-only;
- данные считаются через существующие репозитории;
- если расчёт дорогой, загружать лениво.

## 20. Нижняя панель действий

Нижняя панель закреплена внизу окна.

### 20.1. Режим просмотра

Кнопки:

- `Редактировать`;
- `Закрыть`.

Дополнительные действия в dropdown:

- открыть задачи проекта;
- создать задачу в проекте;
- дублировать проект;
- архивировать проект;
- удалить проект.

## 23. Данные проекта

Окно получает:

- `project_id`;
- либо объект проекта;
- либо DTO проекта, если в архитектуре уже есть DTO.

Поток данных:

1. Открытие окна по `project_id`.
2. Загрузка проекта.
3. Загрузка справочников.
4. Загрузка связанных сущностей.
5. Загрузка статистики проекта.
6. Заполнение формы.
7. Режим просмотра по умолчанию.
8. Переход в редактирование по кнопке или двойному клику.
9. Валидация.
10. Сохранение.
11. Обновление списка проектов и связанных задач.

## 24. Модель данных

Проверить наличие полей:

- id;

- priority;
- parent_project_id;

- force_recurrence;

- color_marker;
- topic_marker;
- repo_catalog;
- task_types;

- wiki;
- archived.

Если поля отсутствуют, не ломать модель. Добавлять только безопасные миграции или адаптеры совместимости.

## 25. Связи проекта

Если сейчас связи хранятся в текстовых полях с ID, необходимо подготовить адаптацию к нормализованному представлению.

Рекомендуемая универсальная таблица связей:

```text
entity_links
  id INTEGER PRIMARY KEY
  source_type TEXT NOT NULL
  source_id INTEGER NOT NULL
  target_type TEXT NOT NULL
  target_id INTEGER NOT NULL
  relation_type TEXT NULL
  created_at TEXT
  updated_at TEXT
```

Для проекта:

```text
source_type = 'project'
source_id = project_id
target_type = 'task' | 'project' | 'map' | 'note' | 'object' | 'file' | 'wiki' | 'repository'
target_id = id связанной сущности
```

Если такая таблица уже есть, использовать её.

## 26. Валидация

При сохранении проверить:

- название проекта не пустое;
- дата обновления корректна;
- priority входит в допустимый список;
- parent project не равен текущему project_id;
- parent project не создаёт цикл;
- task priority preset корректен;
- force recurrence корректен;
- linked map/note/object существуют, если заданы;
- task types не содержат дубликаты;
- repo_catalog является строкой допустимой длины;
- wiki является валидной ссылкой или допустимым внутренним идентификатором;
- archived является boolean.

Ошибки показывать рядом с полем или в верхней зоне формы.

Форма не должна закрываться при ошибке сохранения.

## 27. Горячие клавиши

Добавить поддержку:

- `Ctrl+E` - редактировать всю форму;
- `Ctrl+S` - сохранить;
- `Ctrl+Enter` - сохранить и закрыть;
- `Esc` - закрыть или отменить;
- `Delete` - удалить выбранный chip связи или тип задачи, если фокус находится в соответствующем блоке;
- `Enter` - подтвердить локальное редактирование поля;
- `Ctrl+L` - добавить связь, если фокус в блоке связей.

## 28. QSS-стилизация

Окно должно использовать текущую тёмную тему MindNavigator.

Требования:

- фон окна: тёмный сине-графитовый;
- карточки: чуть светлее основного фона;
- поля: тёмные, с мягкой рамкой;
- hover: мягкое осветление;
- focus: фиолетово-синяя акцентная рамка;
- disabled: muted-состояние;
- dropdown: тёмное меню;
- chip: компактный, скруглённый;
- danger-кнопки: красный акцент;
- primary-кнопки: фиолетово-синий акцент;
- чекбоксы: в текущем стиле приложения.

Не менять глобальную цветовую схему.

## 29. Пустые состояния

```text
Репозитории не указаны

```

## 30. Производительность

Требования:

- окно должно открываться быстро;
- статистику проекта можно загружать лениво;
- связанные сущности загружать пакетно;
- большие списки проектов и задач в dropdown должны поддерживать поиск;
- не блокировать UI при чтении каталогов или проверке путей;
- не выполнять тяжёлые операции в UI-потоке.

## 31. Совместимость

Необходимо сохранить:

- текущую работу ProjectsWorkspace;
- список проектов;
- фильтрацию задач по проекту;
- запрет удаления проекта, если такой запрет уже есть;
- архивирование проекта, если оно реализовано;
- связанные задачи и проекты;
- текущие поля проекта;
- текущие миграции и формат хранения.

Старую форму не удалять до полной проверки новой.

## 32. Критерии приёмки

Задача считается выполненной, если:

- новое окно открывается из списка проектов;
- существующий проект корректно отображается;
- форма открывается в режиме просмотра;
- кнопка `Редактировать` переводит всю форму в режим редактирования;
- каждое редактируемое поле можно редактировать по двойному клику;
- одиночный клик по parent project открывает родительский проект;
- одиночный клик по связанной задаче открывает задачу;
- одиночный клик по связанной карте/заметке/объекту открывает соответствующую сущность;
- верхний блок содержит название, область, дату, приоритет и parent project;
- левая колонка содержит основное, связи, типы задач, репозитории/wiki;
- правая колонка содержит свойства, иерархию/правила, поведение задач и статистику;
- связи отображаются как чипы;
- типы задач отображаются как чипы;
- можно добавить и удалить связь;
- можно добавить и удалить тип задачи;
- archived отображается как чекбокс;
- parent project не допускает циклов;
- данные сохраняются;
- при ошибках сохранения форма не закрывается;
- список проектов обновляется после сохранения;
- цветовая схема соответствует MindNavigator;
- старый функционал проектов не сломан.

## 33. Ограничения

Не реализовывать сложную систему управления проектами сверх текущей модели.

Не менять глобальную архитектуру приложения без необходимости.

Не менять цветовую схему.

Не ломать существующие таблицы базы данных.

Не удалять старую форму до проверки новой.

Не смешивать UI-код с бизнес-логикой сохранения.

Не хранить новые связи только как текстовые ID, если уже есть универсальный механизм связей.
